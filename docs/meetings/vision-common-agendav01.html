비전 공통 형식 — 정할 것 · 논의할 것

buddy-guard · 감시 카메라(outer, 팀원) × 작업자 카메라(inner, 두혁) · 시간 표기는 KST
이 파일 쓰는 법
  1. 표의 결정 칸에서 "추천대로" 또는 "변경"을 고르고, 변경이면 내용을 적어요. Part 2는 결론과 담당을 적어요. 입력 내용은 이 브라우저에 자동 저장돼요.
  2. 추천값이나 설명 문구 자체를 고치고 싶으면 ✏️ 문구 편집을 켜고 글자를 바로 고쳐요.
  3. 회의가 끝나면 📋 회의록 Markdown 복사 → docs/meetings/YYYY-MM-DD.md에 붙여 넣기.
  4. 입력·편집한 상태를 팀원과 공유하려면 💾 HTML 저장 → 받은 파일로 저장소의 이 파일을 덮어쓰고 커밋·PR.
편집 모드 켜짐 — 점선 칸의 글자를 클릭해서 고칠 수 있어요. 고친 문구는 💾 HTML 저장을 눌러야 파일에 남아요.
🎯 이 회의의 목적: 감시 카메라(outer)와 작업자 카메라(inner) 코드가 주고받는 데이터의 모양을 똑같이 맞추는 것. 형식만 먼저 고정되면 각자 따로 개발해도 나중에 그대로 맞물려요.

Part 1. 정해야 할 것 추천값 확인만 17 / 17 결정

A. 사람 한 명의 데이터 모양 (Person)

#정할 것추천이유결정
A1좌표 단위픽셀 (예: 320, 240)감시 구역 좌표가 이미 픽셀이고, 화면에 그려서 확인하기 쉬움
A2좌표 원점·방향왼쪽 위 (0,0), 오른쪽으로 x 증가, 아래로 y 증가이미지 표준. 쓰러짐 판정의 '머리가 내려감 = y가 커짐'으로 통일
A3박스(bbox) 표기(x1, y1, x2, y2) 왼쪽 위·오른쪽 아래YOLO 계열 결과가 보통 이 형태라 변환이 적음
A4관절 이름·개수COCO 17개, 아래 이름 목록 그대로팀원(발목)·두혁(어깨·엉덩이)이 같은 이름으로 꺼내 써야 함. 다른 모델도 detector 안에서 17개 이름으로 바꿔서 내보냄
A5관절이 안 보일 때17개 항상 다 넣고 안 보이면 신뢰도 0'이 관절이 있나?' 확인 코드가 필요 없음. 쓰는 쪽에서 신뢰도로 걸러냄
A6신뢰도 기준값사람 0.5, 관절 0.3 (config.yaml 공통값)둘이 다르면 같은 장면에서 한쪽만 사람이 있다고 판단함
A4 관절 이름 17개 (이대로 복사해서 사용)
nose · l_eye r_eye l_ear r_ear · l_shoulder r_shoulder l_elbow r_elbow l_wrist r_wrist · l_hip r_hip l_knee r_knee l_ankle r_ankle
l_/r_는 화면 기준이 아니라 찍힌 사람 본인 기준 왼쪽/오른쪽 (COCO 약속). 웹캠 미리보기는 거울처럼 뒤집혀 보일 수 있지만, 우리 규칙은 대부분 양쪽 중간점을 써서 결과에는 영향이 없음.

B. 한 프레임의 결과 모양 (Detection)

#정할 것추천이유결정
B1결과에 함께 넣을 것카메라 이름(outer/inner), 찍힌 시각, 화면 가로·세로, 사람 목록, 처리 시간(ms)쓰러짐(2초 지속)·부재(5초 0명)는 시간이 꼭 필요. 처리 시간으로 FPS 계산
B2사람이 없을 때빈 목록 [] (None 아님)for p in persons:가 오류 없이 0번 돎
B3여러 명일 때전부 넣고 신뢰도 높은 순 정렬1명만 필요한 쪽은 첫 번째만 꺼내면 됨

C. 카메라가 주는 화면 모양

#정할 것추천이유결정
C1색 순서카메라 모듈에서 BGR로 통일⚠️ OpenCV(USB)는 BGR, picamera2(CSI)는 설정에 따라 RGB로 줄 수 있음. 다르면 같은 모델에서도 결과가 달라짐
C2해상도둘 다 640×480, config.yaml 고정감시 구역 좌표는 해상도에 따라 달라짐. 바꾸면 감시 구역 다시 찍기
C3회전·반전config.yaml에 카메라별 flip (none / h / v / both)거꾸로 달린 카메라는 서 있는 사람을 쓰러짐으로 판정할 수 있음
C4읽기 실패 시read()가 None 반환, 2초 넘게 이어지면 device_error 이벤트카메라가 빠져도 프로그램이 멈추지 않고, 조용히 고장 나지도 않게

D. 함수 이름과 호출 방법

#정할 것추천이유결정
D1카메라cam = Camera("outer") → frame, ts = cam.read()두 카메라를 같은 모양으로 사용
D2디텍터det = Detector() (모델은 한 번만 로드) → det.detect(frame, cam="outer", ts=ts)매번 로드하면 느려짐
D3결과 꺼내기result.persons[0].keypoints["l_shoulder"] → (x, y, conf)—
D4가짜 디텍터FakeDetector(pose="stand" / "lying" / "none")도 같이 만들기모델이 없어도 둘 다 바로 개발 시작 가능
⭐ D4 FakeDetector가 중요한 이유: 모델이 아직 안 정해져도 가짜 결과로 둘 다 바로 개발을 시작할 수 있음. 팀원은 가짜 사람으로 감시 구역 판정을, 두혁은 가짜 누운 자세로 쓰러짐 판정을 먼저 만들고, 진짜 모델이 나오면 Detector로 바꿔 끼우기만 하면 됨.

Part 2. 논의해야 할 것 답이 정해져 있지 않음

#주제왜 논의가 필요한가참고 · 선택지결론담당
P1포즈 모델 선택카메라 2대 + Pi4 CPU만으로 속도가 나올지가 가장 큰 위험후보: YOLO nano 포즈 / MoveNet Lightning / MediaPipe Pose. 기준: 2대 동시 카메라당 5 FPS 이상. 실험 마감일 정하기
P2① 공통 형식 PR 작성자한 명이 써야 충돌이 없음추천: 두혁 (detector 담당이라 형식과 가장 가까움)
P3② 카메라 · ③ 디텍터 담당과 시작 시점①이 dev에 merge된 뒤 시작해야 함추천: ② 카메라 = 팀원, ③ 디텍터 = 두혁
P4새 이벤트 이름 확정부재·작업자 수 결과를 logic에 넘기는 이벤트 이름이 필요후보: guard_absent / guard_present (outer), worker_count (inner), pose (양쪽)
P5쓰러짐 기준값을 카메라별로 나눌지바깥은 옆에서, 안쪽은 위에서 비춰 같은 기준이 안 맞을 수 있음① 하나로 공통 ② config에 fall.outer.* / fall.inner.* 분리. 측정해 보고 정하기로 해도 됨
P6카메라 설치 위치 · 각도쓰러짐 판정은 전신이 보여야 함. 각도가 바뀌면 기준값 다시 측정바깥: 1.5~2m 거리, 약간 높게. 안쪽: 모형 천장 모서리에서 비스듬히. 고정 방법(거치대·테이프)
P7common/ 수정 규칙공통 파일만 충돌이 날 수 있는 곳추천: 고치기 전 채팅으로 먼저 알리기 + PR은 둘 다 Approve
P8테스트 영상 공유영상은 용량이 커서 Git에 안 올림공유 드라이브 폴더 위치, 파일 이름 규칙 (예: 20261120_inner_lying_01.mp4)
P9라즈베리파이 사용 시간표1대를 둘이 나눠 써야 함오전/오후 나누기, 사용 후 git status 깨끗하게 두기
P10리뷰 · 소통 약속PR이 오래 대기하면 두 브랜치가 멀어짐리뷰 24시간 안에, PR은 하루치 작은 단위로
P11인터페이스 변경 절차나중에 형식을 바꿀 때 한쪽만 바꾸면 깨짐추천: interface.md 버전 올리기 + 둘 다 Approve + 채팅 공지
P12기한이슈마다 기한 칸이 비어 있음#1~#7 이슈별 KST 날짜 정하기

📄 vision/common/detector.py
"""공통 디텍터 — 반환 형식은 docs/interface.md v2와 반드시 일치."""
from __future__ import annotations

import time
from dataclasses import dataclass, field

# COCO 17 관절 (찍힌 사람 본인 기준 왼쪽/오른쪽)
KEYPOINTS = [
    "nose", "l_eye", "r_eye", "l_ear", "r_ear",
    "l_shoulder", "r_shoulder", "l_elbow", "r_elbow", "l_wrist", "r_wrist",
    "l_hip", "r_hip", "l_knee", "r_knee", "l_ankle", "r_ankle",
]


@dataclass
class Person:
    bbox: tuple[int, int, int, int]                   # (x1, y1, x2, y2) 픽셀, 왼쪽 위 원점, 아래로 y 증가
    keypoints: dict[str, tuple[float, float, float]]  # 17개 항상 존재: 이름 -> (x, y, conf), 안 보이면 conf=0
    conf: float                                       # 사람 신뢰도 0~1


@dataclass
class Detection:
    cam: str                         # "outer" | "inner"
    ts: float                        # 프레임 촬영 시각 (epoch 초)
    width: int
    height: int
    persons: list[Person] = field(default_factory=list)  # 없으면 [], 신뢰도 높은 순
    infer_ms: float = 0.0


class FakeDetector:
    """모델 없이 개발할 때 쓰는 가짜 디텍터. pose='stand' | 'lying' | 'none'"""

    def __init__(self, pose: str = "stand"):
        self.pose = pose

    def detect(self, frame, cam: str, ts: float | None = None) -> Detection:
        h, w = (480, 640) if frame is None else frame.shape[:2]
        ts = time.time() if ts is None else ts
        if self.pose == "none":
            return Detection(cam, ts, w, h, [])
        if self.pose == "stand":   # 화면 가운데 서 있는 사람
            bbox = (280, 100, 360, 420)
            kp = {k: (320.0, 100 + i * 18.0, 0.9) for i, k in enumerate(KEYPOINTS)}
        else:                      # 바닥에 누운 사람
            bbox = (150, 360, 470, 430)
            kp = {k: (150 + i * 18.0, 395.0, 0.9) for i, k in enumerate(KEYPOINTS)}
        return Detection(cam, ts, w, h, [Person(bbox, kp, 0.9)])


class Detector:
    """진짜 모델 디텍터 — ③ 브랜치(feat/2-common-detector)에서 구현."""

    def __init__(self, model_path: str = "models/pose.onnx"):
        raise NotImplementedError("③에서 구현 예정. 지금은 FakeDetector 사용")

## v2 — 비전 공통 형식 (YYYY-MM-DD 합의: 두혁, 팀원)

### 좌표 규칙
- 단위: 픽셀 / 원점: 왼쪽 위 (0,0) / 오른쪽으로 x 증가, 아래로 y 증가
- bbox: (x1, y1, x2, y2) = 왼쪽 위, 오른쪽 아래

### Person
- bbox, keypoints(COCO 17개, 항상 전부 존재, 안 보이면 conf=0), conf

### Detection
- cam("outer"|"inner"), ts(epoch 초), width, height, persons(없으면 [], 신뢰도 높은 순), infer_ms

### 카메라 출력
- 색 순서 BGR 통일 / 640×480 / flip은 config에서 / 읽기 실패 시 None

### 바꾸는 법
- 이 형식을 바꾸려면 버전을 올리고 두 사람 모두 PR에서 Approve
