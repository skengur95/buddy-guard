# buddy-guard 프로젝트 배경 (docs/project-context.md)


> 최종 정리: 2026-11-21 (KST). 상황이 바뀔 때마다 파일 갱신


## 1. 무엇을 만드나
- 과정: HYUNDAI AI Insight Campus 온디바이스 AI 과정 팀 별도 프로젝트 (두혁, 원석)
- 주제: 현장 안전 모니터링 온디바이스 AI · 라즈베리파이 4 + 부품 키트
- 컨셉: 탱크·맨홀 등 **밀폐공간 작업자(안) + 감시인(밖) 2인 1조**
  1. 바깥 감시인이 감시 구역에서 사라지면(기본 5초) → 안쪽 작업자에게 경보
  2. 감시인이든 작업자든 쓰러지면 → 유예 없이 경보 (오경보 방지를 위해 누운 자세 약 2초 지속으로 확정)
  3. 감시인 교대 시 사인(RFID 카드 또는 버튼, 확장: 손동작) → 60초 유예 + 작업자에게 알림. 유예 중에도 쓰러짐·가스는 계속 감시
  4. 안쪽 가스(MQ-2, MQ-7)·온도(BME280) 기준 초과, 불꽃 감지 → 경보
- 과제 감지 대상과의 연결: 위험구역 침입 감지(→ 감시 구역 이탈 감지로 응용) / 쓰러짐 / 화재·연기 / 가스·온도 이상
- 안전 고지: 교육용 시제품. MQ 센서는 ppm 정밀 측정이 어려워 "깨끗한 공기 대비 비율"로 판정한다. 인증된 가스 측정기를 대체하지 않는다.


## 2. 하드웨어 구성 (요약)
- Raspberry Pi 4 1대가 바깥·안쪽을 모두 담당
- 바깥: CSI 카메라(감시 구역), RFID(RC522)·교대 버튼, 확인 버튼, 바깥 부저·LED
- 안쪽(모형 탱크): USB 카메라 + LED 조명, MQ-2·MQ-7(→ ADS1115, 전압 분배 10k/20k), BME280(I2C), 불꽃 센서(GPIO17), 안쪽 부저·LED
- MQ 센서 히터는 외부 5V 전원, GND는 공통 연결. GPIO는 3.3V 전용.
- 핀맵은 `config.yaml`의 `pins:`와 `docs/wiring.md`가 기준.


## 3. 소프트웨어 구조
- 스레드: 비전(바깥/안쪽) · 센서 · 입력 → 큐(`core/bus.py`) → 메인 루프(상태 머신) → 경보 출력 · 기록(`events.db`)
- 상태: IDLE(예열) → PRECHECK(점검) → WORKING ↔ HANDOVER(교대 60초) → ALARM. 경보는 여러 개 동시 가능(집합으로 관리)
- 경보 우선순위: 화재 > 쓰러짐(작업자 → 감시인) > 가스·온도 > 감시인 부재 > 장치 이상
- 장치 이상(FR-12): 프레임 2초 이상 없음, 센서 3회 연속 실패 → 경보 (조용히 멈추지 않기)


### 폴더와 그 이유
| 폴더 | 이유 | 나중에 쓰이는 곳 |
|---|---|---|
| `core/` | 모두가 쓰는 기본 약속(Event, 큐, KST 시간) | 모든 모듈 |
| `vision/common·outer·inner/` | 누가 고치는지 기준으로 분리 → 충돌 감소 | 통합 시 main.py가 스레드로 실행 |
| `sensors/`, `io_devices/` | 하드웨어 교체가 다른 코드에 영향 없게 | 센서 교체 시 이 폴더만 수정 |
| `logic/`, `alerts/` | "무엇을 감지했나"와 "경보를 울릴까"를 분리 | 상태 머신·경보 판단 |
| `config.yaml` | 숫자를 코드 밖으로 → 코드 수정 없이 조정 | 테스트·시연 당일 튜닝 |
| `tests/` | 고친 코드가 기존 기능을 깨지 않는지 자동 확인 | PR 전 `pytest` |
| `tools/` | 개발용 보조(감시 구역 찍기, 센서 보정, FPS 측정) | 개발 중 |
| `sim/` | 하드웨어 없이 시나리오 재현 | 통합 테스트, 시연 백업 |
| `docs/` | 결정과 근거 기록 | 보고서·발표 원재료 |
| `models/`, `data/` | 용량이 커서 Git 제외 | 공유 드라이브로 공유 |
